# 文风库 · 总览（★文风工坊主文档 · 文风与内容分离）

> **一句话**：把「文风」从「内容」里剥出来，单独维护成一个**可复用、可成长、可调参、可切换、带范文例库**的独立单元——**文风包**。多套文风包并存。
>
> **★默认文风模式＝融合（见 `_文风模式配置.md`，工作流级配置的单一真相源）**：本工作流默认**每本书都用"融合文风"**——立项时从现有多套文风包里取 **2+ 套当参考原料、一书一配方**，按本书题材**智能合成**一套本书专属《写作风格卡》，而不是单选一套包。现有文风包＝**融合原料/调色盘**。（作者可对某本书显式声明退化为单包，见配置文件第五节。）本总览下文描述的"选用/挂载/成长"机制在融合模式下依然成立，只是"选一套"升级为"定融合配方"。
>
> **★文风工坊是创作主管线里的一个阶段（成文层），不只是资源库**：章节工坊把"写什么"定到句意稿颗粒度后，**由文风工坊这一步把内容"制作"成正文**——`正文生成`（下笔成文）和 `润色定稿`（打磨声音）两个 prompt 就归属文风工坊。管线：`章节工坊(内容层：…→句意稿) → 文风工坊(成文层：正文生成→润色定稿) → 独立校验`。
>
> **对应的优化关系**：文风工坊由「维护工坊·文风优化分支」（`用词优化` 四步）专门优化；章节工坊等内容层由「维护工坊·架构优化分支」优化。两者的分工见 `../prompts/架构优化-总纲.md`。**北极星**：输入范文 → 用词优化逆向拆骨架 → 文风差距回填文风工坊、内容/结构差距转交架构优化 → 整个工作流自优化。
>
> **为什么要拆**：以前"这本书是什么声音"散落在 `正文生成`/`场面调度`/`知识库`/每本书的风格卡里，改一处顾不上别处；范文里的好例子又因为怕污染通用工作流（用词优化铁律3"不举例只抽象"）而不敢留。文风工坊给例子开一个**受隔离的合法出口**：例子只活在被选用的那一套文风包里，随包挂载给选它的书，**不外泄到通用引擎层、不污染别的文风包**。

## 一、三层文风架构（★核心，先看懂这张分层图）

写一本书的"声音"由三层叠出来，从通用到专属：

| 层 | 在哪 | 讲什么 | 例子？ | 谁共用 |
|---|---|---|---|---|
| **① 通用引擎层** | `knowledge/去AI味与叙事质感`、`优秀网文写作法`、`描写与逻辑规范`；`正文生成`/`场面调度`/`句意稿` 的通用规则 | **"怎么写好"**——落地、防AI味、句子呼吸、比喻门槛。跨题材通用的写作技法。 | ❌ **绝不夹带任何一篇范文的具体文字**（防污染，保通用；由用词优化铁律3守住） | 所有书 |
| **② 文风包层** | `ENGINE/文风库/<文风名>/` | **"这一类声音长什么样"**——参数取值 + 抽象风格纪律 + **范文例库** + 反馈成长账本 | ✅ **例子在这里合法**（隔离在包内，随包挂载给选它的书） | 选用同一包的书 |
| **③ 本书文风层** | `BOOKS/<书>/01-设定/写作风格卡.md`（+ 可选 `黄金样张.md`） | **"这一本书"的具体声音**——选定文风包在本书上的实例化 + 本书特化 override | ✅ 本书专属样张 | 只此一本 |

**加载优先级（写正文时）**：③本书写作风格卡（有黄金样张以样张为准）＞ ②本书选定的文风包 ＞ ①通用引擎层。冲突时越专属越优先。

**分离带来的三个能力**：
1. **可复用**：一套"都市异闻情感向"文风包，多本同类书共用，不用每本重写。
2. **可成长**：范文 + 用户意见持续喂进包里（见第四节成长闭环），包越跑越准。
3. **可切换/可调参**：换书换包即换声音；调包内参数即微调文风（见第二节）。

## 二、可调参数机制

每套文风包在 `00-文风配置.md` 里，用一组**参数刻度**把这套声音量化下来（如"句长节奏=2/短促、意象密度=1/克制、口语网感=5/满"）。参数维度的权威定义见 **`_文风参数体系.md`**（9个维度 + 每维度取值刻度含义）。

- **调参数 = 微调文风**：想让某本书"对话再多点、意象再收一点"，改的是该书写作风格卡里对文风包参数的 override，不动包本身。
- **参数不是硬指标、是倾向标尺**：它给正文生成/句意稿一个"往哪个方向靠"的锚，不是"必须几句话"的死规定（同少年向"念出来顺不顺"哲学）。
- 参数还挂钩现有机制：意象密度↔`意象授权点`、硬核精准度↔句意稿的"锁精准"、叙事距离↔叙事人称/视角。

## 三、选用与挂载（文风包怎么进到写书管线）

```
立项问答·维度8"文风基调"（★默认融合模式，见 _文风模式配置.md）
   → 从 文风库 现有包里定"融合配方"：主色包 + 1+辅色包(+点缀包)，各取哪些维度、冲突裁决
     （作者显式声明时才退化单包；没有贴合成分包就先按第五节新建再纳入）
   → 融合配方写进《立项书》#8
        ↓
新建项目 步骤2.5（★按配方智能合成，不是单包实例化）
   → 依据立项书#8 融合配方，合成 BOOKS/<书>/01-设定/写作风格卡.md：
       · 9维参数逐维挑取（记每维取自哪套成分包）——不做机械加权平均
       · 融合各成分包 01-风格纪律 的贴题材倾向（去冲突）
       · 从各成分包 02-范文例库 抽贴题材例子，拼成"本书融合例集"清单
        ↓
正文生成 / 句意稿 / 润色定稿 / 独立正文自查（每章）
   → 加载清单里，除了本书《写作风格卡》（已含融合结果），还按"融合例集清单"
     挂载各成分包 02-范文例库里那几个例子：
       · ★按需抽 1-3 个贴本章场景/情绪的例子——这就是"用大量例子同步文风"
   → ★ 例子只在这一步、只对本书生效；不写进通用引擎层、不外泄别的书。
```

> **★与通用引擎层的红线**：`正文生成`/`场面调度` 等**所有书共用的 prompt/knowledge 正文里，永远只放抽象提示词，绝不放范文例子**。例子的唯一合法居所是**文风包的 `02-范文例库/`**，靠"挂载"而非"写死"进入某本书的写作。这条红线是文风工坊成立的前提，等价于用词优化铁律3在新架构下的落地。

## 四、成长闭环（★可成长的文风机制：范文 + 用户意见两条喂料）

一套文风包不是一次写死的，它靠两条料持续长：

**A. 范文喂料（走"用词优化"四步管线——★维护工坊·文风优化分支，专门优化本工坊）**
见 `../prompts/用词优化-总览.md`。跑法：**指定"针对哪个文风包"** + 一篇标杆范文一章 → 逆向提取骨架 → 换agent盲重建 → 只比文风差距 → 抽象回填。回填**分三路落地**：
1. **通用执行原则**（换任何题材都成立的手艺）→ 回填 ①通用引擎层（仍守铁律3：无例子）。
2. **该文风的个性倾向** → 回填 ②该文风包的 `01-风格纪律`（抽象）。
3. **★范文例子本身**（带批注：好在哪/示范了哪个参数/怎么仿）→ 收进 ②该文风包的 `02-范文例库/`（例子合法，因为隔离在包内）。
   > 每轮四步的中间产物落 `<包>/04-优化留档/`（一包一份成长史，见该目录下 `_说明.md`）。

**B. 用户意见喂料（轻量"文风反馈"，不必跑整条四步管线）**
作者对某本书/某段正文的文风给意见（如"主角内心戏太多、对话不够呛"）→ 归到**该书选定文风包的 `03-反馈账本.md`**（记：意见原文 + 抽象成什么倾向 + 拟怎么调）。攒够后，把稳定的倾向抽象进 `01-风格纪律`（或触发一次 A 的范文跑档验证）。这就是"在维护工坊里单独输出文风反馈并优化到工坊中"的落地。

> 两条料的共同纪律：进 `01-风格纪律` 的都要**抽象到"换本同类书仍成立"**；进 `02-范文例库` 的可以是具体例子，但**只准留在包内**。

## 五、多套文风包并存 + 新建一套

`ENGINE/文风库/` 下**一套文风一个文件夹**，可任意多套（如 `都市异闻情感向/`、`末世副本流/`、`西幻契约情感向/`……）。当前已有包见文末索引。

**新建一套文风包**（"自定义/新建"时）：
1. 建目录 `ENGINE/文风库/<文风名>/`，按下面的固定结构建 5 个槽位。
2. 填 `00-文风配置.md`：9 维参数取值 + 一句话声音定位 + 适配题材范围 + 挂载清单。
3. 填 `01-风格纪律.md`：这套声音的抽象倾向（先粗后细，靠成长闭环长）。
4. `02-范文例库/`、`03-反馈账本.md`、`04-优化留档/` 先留空骨架，随成长闭环填。

### 文风包固定结构（一包五槽位）

| 槽位 | 内容 | 进依赖图？ | 版权 |
|---|---|---|---|
| `00-文风配置.md` | 参数取值 + 声音定位 + 适配题材 + 挂载清单 | ✅ 进图 | 自创 |
| `01-风格纪律.md` | 抽象风格倾向（可跨同类书） | ✅ 进图 | 自创 |
| `02-范文例库/` | 带批注的范文片段（例子合法区） | ❌ SKIP（数据） | ⚠含第三方，gitignore |
| `03-反馈账本.md` | 用户意见 + 跑档结论的抽象汇总 | ✅ 进图 | 自创 |
| `04-优化留档/` | 用词优化每轮四步中间产物 | ❌ SKIP（数据） | ⚠含范文原文，gitignore |
