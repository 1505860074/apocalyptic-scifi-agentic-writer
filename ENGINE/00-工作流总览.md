# 工作流总览 · V3

> **V3核心哲学**：V2 是"生长模式"——大纲随写作演进。V3 在此基础上引入**"拆分+校验"**——每个步骤只做一件事、只产出一种内容，关键衔接点有独立校验把关。杜绝"一个 agent 同时当写手和校对"带来的幻觉和杂糅。

---

## V2 → V3 变化一览

| 问题（V2） | 改法（V3） |
|------------|-----------|
| P6 边写边自查——写手和校对是同一个人格，自查流于形式 | 拆成 P6（纯写）+ **V4（独立自查，新 agent）** + P6fix（根据报告修） |
| P7 五轮润色挤在一次对话里，后半段注意力稀释 | 精修＝每轮独立调用；**日更默认合并为一道润色（P7），初稿问题多时才拆 P7a/P7b**（V3.1：加工链越短，人味越不容易被磨平） |
| P5 章纲和焦点卡一次生成，事件设计和体验设计混在一起 | 拆成 P5a（章纲节拍）+ P5b（焦点卡），中间加 **V3 校验** |
| 全流程只在最后一步（P7末尾）有自检，没有中途把关 | 6 个 **V 校验门**插入关键节点，每个都是独立 agent 调用 |
| P4 四件事一次做完，态势分析出错则后续全错 | 拆成 P4a（分析+反向发现）+ P4b（大纲+状态更新），中间断点清晰 |
| P8 修改后没有回归检查 | 加 **V6 回归校验** |

## 二、V3 新增的核心概念

### 执行步骤 vs 校验门

- **P 步骤**：做事的步骤，有产出文件
- **V 校验门**：检查的步骤，产出校验报告，不修改任何创作内容。**V 步骤和它前面紧邻的 P 步骤必须是两次独立的 agent 调用**——这是防幻觉的核心设计。

### 为什么 V 步骤必须独立调用

同一个 agent 在生成内容后立即自查 = 学生给自己的卷子打分。它的"创作脑"还在活跃，倾向于自圆其说。新开一次对话、带着 fresh context 只做审查——这时候 agent 是读者而非作者，更容易发现问题。

### 输出文件命名约定

- P 步骤产出的文件命名不变（如 `焦点卡-第X章.md`、`第X章-XXX.md`）
- V 步骤产出独立的校验报告（如 `自查报告-第X章.md`），不是挂在正文后面的附录
- P6fix 修正时，覆盖更新正文文件，不额外产生文件

## 三、完整步骤清单

### 架构工坊（4步 + 1验）

| 步骤 | 角色 | 做什么 | 产出 |
|------|------|--------|------|
| **P1** | 世界观+金手指设计师 | 定死灾变物理规则和金手指机制；大秘密仅留模糊方向 | `世界观设定卡` `金手指卡` |
| **P2** | 人物设计师 | 逐人建卡（主角三层，配角双层），不定死命运节点 | `人物卡`（一次一人） |
| **P3** | 架构师 | 收束世界基底（物理事实定死）+ 故事种子（前三章写死，后续方向模糊） | `世界基底` `故事种子` |
| **V1** ★ | 架构校验官 | **独立审查**：P1+P2+P3共五个文件之间有无逻辑矛盾 | `架构校验报告` |

### 写作工坊 · 演进（每3-5章，2步 + 1验）

| 步骤 | 角色 | 做什么 | 产出 |
|------|------|--------|------|
| **P4a** | 态势分析师 | 回看已写3-5章正文，做态势分析 + 反向伏笔发现（自下而上：S→M→G） | `态势分析报告` `更新伏笔DAG` |
| **P4b** | 大纲规划师 | 基于P4a的分析结果，生成接下来3-5章的局部大纲 + 更新演进状态卡 | `局部章纲` `更新演进状态卡` |
| **V2** ★ | 演进校验官 | **独立审查**：局部大纲是否与人物状态、已揭示信息、伏笔计划一致 | `演进校验报告` |

### 写作工坊 · 日更（每章，5步 + 3验）

| 步骤 | 角色 | 做什么 | 产出 |
|------|------|--------|------|
| **P5a** | 章纲设计师 | 根据局部大纲，设计本章节拍表（事件、L级、情绪温度） | `章纲节拍表-第X章` |
| **P5b** | 焦点卡设计师 | 基于节拍表，设计读者体验 + 加载清单 | `焦点卡-第X章` |
| **V3** ★ | 焦点卡校验官 | **独立审查**：焦点卡字段是否完整、情绪温度是否标注、L3定位是否明确、加载清单是否准确 | `焦点卡校验报告-第X章` |
| **P6** | 正文写手 | 手持焦点卡，按三层加载顺序纯写正文。**不查，只写。** | `第X章-XXX.md`（初稿） |
| **V4** ★★ | 独立自查官 | **独立审查**（最关键的新步骤）：五类自查全部执行，产出独立报告 | `自查报告-第X章.md` |
| **P6fix** | 修正写手 | 根据 V4 自查报告，逐一修正正文中的问题 | 覆盖更新 `第X章-XXX.md` |
| **P7a** | 出戏+去味编辑 | 出戏自查 + 去AI味（原P7轮1+2合并），强调执行纪律 | 覆盖更新正文 |
| **P7b** | 少年向+校验编辑 | 少年向定稿 + 三层校验 + 符号标点（原P7轮3+4+5合并） | 覆盖更新正文 |
| **V5** ★ | 最终交付官 | **独立审查**：禁区检查、润色前后对比、反向抽查念一遍 | `定稿确认报告-第X章` |

> ★★ V4 是 V3 最重要的新增步骤。它是正文和润色之间的"防火墙"——确保进入 P7 的正文已经过了独立审查，不是写手自写自夸的产物。

### Review（人工反馈后，1步 + 1验）

| 步骤 | 角色 | 做什么 | 产出 |
|------|------|--------|------|
| **P8** | Review编辑 | 上下文手术：锁一个点 → 拉一条线 → 精准修改 | 覆盖更新正文 + 同步更新DAG/状态卡 |
| **V6** ★ | 回归校验官 | **独立审查**：修改是否破坏了伏笔/衔接/数字一致性 | `回归检查报告` |

## 五、操作话术（更新）

**新书开始**：
- 「进入P1」→ 世界观+金手指
- 「进入P2，先做主角」→ 人物种子
- 「进入P3」→ 种子收束
- 「跑V1」→ 架构一致性校验
- 「进入写作」→ P4a→P4b→V2，然后进入日更循环

**日常写作**：
- 「写第N章」→ 自动 P5a→P5b→V3→P6→V4→**〔P6fix：仅 V4 有必须修时才跑〕**→**P7（去味+少年向+校验+标点，默认一道跑完）**→**〔V5：仅 P7 做了实质改动时才独立跑，否则由 P7 末尾自检代替〕**
  - V3.1 精简：默认日更从 9 步压到约 5–6 步。**核心防幻觉关 V4 保留不动**；砍的是 P6fix 空转、P7 双 agent、V5 与 V4 的重复。既省 token，也少一道"把好东西磨平"的工序。
- 「跑P4」→ 自动 P4a→P4b→V2

**独立操作**（想单独跑某个子步骤）：
- 「只跑P5a，第N章」→ 只出章纲节拍表
- 「只跑P5b，第N章」→ 基于已有节拍表出焦点卡
- 「只跑V4，第N章」→ 只做独立自查
- 「只跑P6fix，第N章」→ 根据自查报告修正
- 「只跑P7a，第N章」→ 只做出戏+去味
- 「只跑P7b，第N章」→ 只做少年向+校验+标点
- 「只跑V5，第N章」→ 只做最终交付检查

**人工 Review**：
- 「修改第X章第Y段，问题：XXX」→ P8 自动拉通上下文
- 「跑V6，修改了第X章」→ 回归校验

**卡住了**：
- 「卡住了，跑P4b」→ 卡文诊断（保持不变）

**状态查询**：
- 「跑V4，最近三章」→ 对最近三章分别做独立自查（追查质量滑坡）

## 六、铁律（V3 更新）

1. **只定物理规则，不定全书结局。** 大秘密留白，在写作中发现。
2. **一次只写一章。**
3. **每章必有 L3。** 没有深度刻画的章节是流水账。
4. **每章必有情绪温度。** 文字的嗓音要跟角色的感受同频。
5. **大纲是活的。** 写完 3-5 章跑一次 P4a→P4b→V2。
6. **伏笔可以"后发现"。** 写作中随手写下的好细节，回头登记到 DAG。
7. **大声念一遍。**
8. **★ V3 新铁律：P 步骤和紧邻的 V 步骤必须是两次独立的 agent 调用。** 写手不自查，校验不写作——这是 V3 防幻觉的基石。
9. **★ V3 新铁律：V4 自查报告必须独立存档。** 不在正文后面挂附录，不用"看一眼没问题"代替逐条执行。
10. **★ V3 新铁律：P6 纯写不查。** 写作时不要分心自查——写完交给 V4 独立审查。
