# 用词优化 · 第4步 · 抽象优化与回填（含迭代闭环）

**做什么**:把第3步的每条差距过两道闸,提炼成对各层的**抽象**优化建议;经作者确认后改对应文风层;并可再跑一轮盲重建-对比,看差距是否收敛。
**输入**:第3步的 `03-对比差距.md`。
**产出**:①对各层的抽象优化建议(《工坊报告》主体);②对文风层的**实际改动(直接落地,不等审批)**;③(可选)下一轮迭代的收敛对比;④**(条件式)《转交清单》**——把内容/结构级残差沿 pipeline 转给 `架构优化-评估提案`(见第四节),接成自动化自优化管线。回填是维护工坊的目的所在——不落地就毫无意义，故**先执行再回报**改了哪。
**落盘**:抽象优化建议写入本轮文件夹 `ENGINE/_用词优化留档/<范文标识>-<日期>/04-优化建议.md`,带溯源头(迭代第 N 轮存为 `04-优化建议-rN.md`)。对文风层的实际改动仍改各层文件本身,不进本目录。

> 先读《用词优化-总览》。本步是回填闸门,铁律3(只抽象不举例)、铁律4(防过拟合)在这里把关。

---

## 一、每条差距过两道闸

- **闸一(防过拟合 · ★分层,非二元)**:不要笼统问"采纳还是丢弃",而是把这条差距拆成两层分别判(见《总览》铁律4):
  - **密度/默认层**——"要不要让工作流默认这么写、写多密?" 与题材/作者强绑定的浓度取向 → **保持工作流现状、不动**(防污染，别把一篇的浓度当通法)。
  - **执行/用词层**——"一旦这种形态**确被启用**(命中授权点，或目标题材确需)，用词/手艺该怎么做才好?" 若能上升为"换任何题材都成立"的通用原则 → 提炼成**条件式**原则("当写X时,用词应……")，进入闸二。
  - 典型结果是"**密度层不动 + 执行层提纯条件式原则**"，而非整条采纳或整条丢。**只有执行层也榨不出通用手艺时,才如实整条丢。**
- **闸二(定位)**:要回填的(通常是执行层的条件式原则)对应工作流哪一层?——知识层规则 / 模板 / prompt。**条件式原则优先挂到对应的授权点机制**(意象授权点 / 闲笔授权点 / 性格速写触发点等)下,让它只在该形态被授权启用时生效,不污染默认。

## 二、产出抽象优化建议（★分三路，按去处定规矩）

回填有三个去处，规矩不同（见《总览》铁律3 文风工坊分区版）：
- **路①：通用引擎层**（`去AI味与叙事质感` / `优秀网文写作法` / `正文生成`的通用文风部分 / `场面调度`的对话）——只放**抽象方向性**原则，**不携带任何范文具体文字**。判定标尺:"换任何一篇范文都仍成立"才算抽象到位。收换任何题材都成立的通用手艺。
- **路②：目标文风包的 `01-风格纪律`**——放**这套文风的个性抽象倾向**（如"这套声音对话更呛、更少内心独白"），仍抽象、不抄原句，但可以是"只对这一类题材成立"的倾向（比通用层松一档）。
- **路③：目标文风包的 `02-范文例库/`**——✅ **可以放范文片段原文 + 批注**（好在哪/示范哪个参数/怎么仿）。例子合法，因为隔离在这一个包内、只随包挂载给选它的书。
- **共同禁区**：三路都**不碰情节/结构/设定层**(铁律2)；例子**绝不进路①/路②**，只进路③。

## 三、回填（直接执行，执行后回报）

- 按建议**三路落地**（去处见第二节）。**直接改、不等作者审批**（防污染靠铁律3/4 与分层过闸在动手时把关，改坏了 git 可回退；把优化真正落到工作流才是本工坊的意义）。
  - **路①/路②（通用层 / 包`01-风格纪律`）**：抽象地改。落地规则文字里**不得夹带范文原句、具体词表/提示词/句式,也不得是嵌了范文确切措辞的总结**。收尾自检:把这篇范文抽走,新加的规则是否依然读得通、依然管用?不行就是没抽象到位,回炉。
  - **路③（包`02-范文例库/`）**：把范文片段 + 批注落到 `ENGINE/文风库/<目标包>/02-范文例库/例-<主题>-<来源>.md`，并在该目录 `_例库索引.md` 登记一行。⚠受版权原文由 `.gitignore` 兜住，批注/索引可留。
- **顺手更新目标包的 `03-反馈账本.md`**：把本轮对比差距的抽象结论汇一笔，标来源轮次（成长纵览用）。
- 改完顺手维护相关文件的 frontmatter,并按项目硬规则重跑 `workflow_map.py`。

## 四、转交内容/结构级残差 → 架构优化-评估提案（★接成自动化自优化管线，条件式）

文风差距三路回填完后，**还剩一类不归本分支管的差距**：闸一里判为**内容/结构级**的（如"盲重建稿情节密度不够/缺一层规划步骤/某节点职责错位"，而非文风；见铁律2）。这类**不在本步硬改**，而是整理成一份**《转交清单》**，**沿 pipeline 流转给 `架构优化-评估提案`**——这就是"输入范文→整个工作流自优化"的第二条腿（第一条腿=文风回填文风工坊）。

- **《转交清单》内容**：每条＝一个内容/结构级差距的**抽象描述**（不抄范文原文）＋ 它疑似暴露了工作流哪一层的结构问题（哪个节点/管线顺序/缺失步骤）＋ 证据是"盲重建 vs 范文"在该维度的系统性差距。
- **★条件式流转（重要）**：
  - 本轮**若存在**内容/结构级残差 → 产出《转交清单》，**继续走 pipeline 到 架构优化-评估提案**（由它按架构标尺评估、决定要不要改结构，再到 改造执行）。
  - 本轮**若是纯文风**、无结构残差 → **到此为止，不触发架构优化**（别为了跑管线硬造结构问题；奥卡姆）。
- **边界**：本步只**转交、不自己改结构**（铁律2：文风分支不碰结构）；改不改、怎么改由架构优化分支判。转交清单落进本轮 `04-优化建议.md` 末尾"转交架构优化"栏，便于追溯。

## 五、迭代闭环（可选）

- 回填后可**再跑一轮 用词优化-盲重建 → 用词优化-对比差距**(用新工作流重新盲写、再对比),看差距有没有缩小。
- 形成闭环,直到收敛或作者叫停。

## 使用方式

- 全程带跑:「跑用词优化-抽象优化与回填」(对比差距产出后)
- 迭代:「再跑一轮盲重建+对比,看差距收敛没」
