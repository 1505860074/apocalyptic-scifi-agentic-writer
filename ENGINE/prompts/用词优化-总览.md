# 用词优化 · 总览（★维护工坊·文风优化分支 · 优化「文风工坊」）

> **这不是写书的工序,是优化工作流本身的工具。** 它跑在写书主管线之外:拿一篇标杆范文当"标准答案",逆向拆出它的骨架 → 让工作流拿同样的骨架**盲写一遍** → 比出差距 → 把差距回填,让工作流的用词和风格逐步逼近范文。
>
> 核心思路 = 把"作者手改→提炼规律→改工作流"这个手动循环,做成可复用的自改进闭环。
>
> **★对应关系:它是「维护工坊」的文风优化分支,专门优化创作主管线里的「文风工坊」（成文层）——既调 `正文生成`/`润色定稿` 的文风,也成长文风工坊消费的「文风包」。** 见 `../文风库/_文风库总览.md`。跑本管线时**必须指定"针对哪个文风包"**(如 通俗少年向)——回填分三路落地:①通用执行原则→通用引擎层(仍无例子);②该文风个性倾向→该文风包 `01-风格纪律`(抽象);③**范文例子本身(带批注)→该文风包 `02-范文例库/`(例子合法,因隔离在包内)**。第③路是对旧铁律3的受控松绑,见下方铁律3。
>
> **★北极星（自优化的两条腿）**:输入范文 → 逆向拆骨架 → 差距同时暴露"文风差距"和"内容/结构差距"。**文风差距**由本分支(文风优化)回填「文风工坊」;**内容/结构差距**转交「维护工坊·架构优化分支」作用于「章节工坊」等内容层(见铁律2 转交机制)。两条腿都走通,才是"输入范文→整个工作流自优化"。

## 输入 / 产出

**输入(可插拔)**:
- **★目标文风包(必填)**:本轮针对 `ENGINE/文风库/` 下的哪一套文风包(如 通俗少年向)。决定第②③路回填落到哪个包、留档落到 `<包>/04-优化留档/`。选材范文应贴近该包的适配题材。
- **标杆范文**:一篇你认可的、比工作流当前产出更好的文本。外部优秀网文 或 项目内定稿章节均可,**跑时指定**。以**一章**为单位(一整篇太大,且骨架提取会失真)。
  > **★选材提示**:范文题材离工作流目标题材越远,可回填的通用项越少、按铁律4丢弃的题材个性越多(密度层几乎都动不了,只剩执行层的条件式手艺能提纯)。所以**优先选贴近目标题材的范文**;若确要用远题材范文,跑前就明确"本轮只提纯通用文风纪律 + 条件式手艺",别指望它能校准整体文风。
- **当前工作流**:ENGINE 各层(现状,作为被优化对象)。

**产出**:
1. 《工坊报告》:逆向骨架 + 盲重建稿 + 差距分析(抽象层)+ 对各层的抽象优化建议。
2. 对工作流各层的实际改动(**直接落地、执行后回报**;不落地则本工坊无意义):①通用引擎层(抽象)、②目标文风包 `01-风格纪律`(抽象)、③目标文风包 `02-范文例库/`(带批注的范文例子)。
3. 本轮四步中间产物落 `ENGINE/文风库/<目标包>/04-优化留档/`(一包一份成长史)。

## 四条铁律（本工坊红线,违反即结果作废；每一步都要遵守）

1. **盲重建**:正向重建的子agent **只拿骨架、绝不接触原文**。看了原文＝作弊,测出来的不是工作流的真实能力。逆向提取的agent 和 盲重建的agent **必须是不同的、互不传原文的**。

2. **只优化文风层（★本条仅约束"用词优化"这条分支）**:骨架喂了相同的情节/人物/节拍 → 情节结构本应一致 → 差距集中在**用词、句子、节奏、质感**。所以本分支的回填**只动文风相关层**(去AI味与叙事质感 / 优秀网文写作法 / 本书写作风格卡 / 正文生成的文风部分 / 场面调度的对话),**不碰情节、结构、设定层**。若发现情节结构也差很多,那多半是"逆向提取没提准",回第1步。
   > **分工说明**:维护工坊现分两条分支——**用词优化**(本分支,文风自优化)与**架构优化**(结构/流程自优化,见 `架构优化-总纲.md`)。"工作流的结构/流程该不该改"属**架构优化分支**的职权,**不在本铁律的禁区之列**;本分支若确认察觉到的是**结构级问题**(而非逆向提取失准),应**转交架构优化分支**处理,别在本分支硬改结构。

3. **通用层/纪律层只抽象;例子只准进文风包的范文例库(★文风工坊架构下的分区版)**:回填有两类去处,规矩不同——
   - **进「①通用引擎层」或「②文风包的 `01-风格纪律`」的**:只能落成**抽象方向性原则**——只说"该往哪个方向调、补哪条通用倾向"(如"该更强调动词贴角色职业"),**不携带任何来自范文的具体文字**。以下三种进这两层一律禁止,出现即作废重写:
     - ❌ **抄范文原句/原词当例子**写进规则("范文里写了X,所以规则加X");
     - ❌ **列举具体词表 / 提示词 / 句式模板**("多用'某某''某某'这类词""按'A于是B'的句式写");
     - ❌ **任何嵌了具体文字的"总结性回填"**——哪怕把范文归纳一遍,只要落地文字里还带着可辨认的范文原文或其确切措辞,也算污染。
     - **验收标尺**:这两层回填后的规则应"**换任何一篇范文来跑都仍然成立**";一旦脱离这篇范文就没意义,即是污染,不能进。
   - **进「②文风包的 `02-范文例库/`」的**:✅ **例子在这里合法**——可以放范文片段原文 + 批注(好在哪/示范哪个参数/怎么仿)。因为它被**隔离在这一个文风包内**,只随该包挂载给选它的书,**绝不外泄到通用引擎层、绝不进别的文风包**。这是文风工坊"用大量例子同步文风"的落地,也是对旧"一刀切不举例"的受控松绑。

   目的没变:保住**通用引擎层的通用性**,别让所有书共用的层被某一篇范文的确切文字污染。区别只是——例子不再是"绝对禁止",而是"关进文风包这个隔离区"。**红线**:例子的唯一合法居所是文风包 `02-范文例库/`;`正文生成`/`场面调度` 等共用 prompt 与通用 knowledge 正文里,永远只放抽象提示词、绝不放例子。

4. **防过拟合 + 分层处理（★非二元，不是"采纳 or 丢弃"）**:一篇范文里,有些特征是**通用网文规律**,有些只是**这位作者/这个题材的个人风格**。但**"丢弃"从来不是整条丢**——每条差距都要拆成两层分别判:
   - **密度/默认层**（要不要让工作流默认这么写、写多密）：与题材/作者强绑定的浓度取向 → **保持工作流现状、不因单篇调默认**（防污染，别把一篇的浓度当通法）。
   - **执行/用词层**（一旦该形态**确被启用**——命中授权点，或目标题材确需——用词/手艺该怎么做才好）：**这一层往往能上升为"换任何题材都成立"的通用原则** → 提炼成**条件式**抽象原则回填（"当写长句/意象时，用词应……"），优先挂到对应的**授权点机制**（意象授权点/闲笔授权点等）下。

   所以典型判法是"**密度层不动 + 执行层提纯条件式原则**"，而非整条采纳或整条丢。宁可不动密度，也别把一篇的浓度当通法；但也别因为"密度层不采纳"就把"该形态下的用词手艺"一起扔了。（例外:不是每条被丢的差距都必然有可提纯的执行原则——执行层确实榨不出通用手艺时，才如实整条丢。）

## 四步管线（用子agent编排,盲测隔离）

```
用词优化-逆向提取 → 用词优化-盲重建 → 用词优化-对比差距 → 用词优化-抽象优化与回填
   (蒸馏骨架)        (换个agent盲写)     (只比文风差距)      (三路回填文风工坊 + 拆出结构残差)
                                                                  │
                                          ┌───────────────────────┴───────────────────────┐
                                          ↓ 文风腿:回填文风工坊(就地)   ↓〔条件式〕内容/结构腿:有结构残差才转交
                                    (到此本轮文风优化完成)      架构优化-评估提案 → 架构优化-改造执行
```

> **★这就是"输入范文→整个工作流自优化"的完整自动化管线**:一条范文进去,文风差距就地回填文风工坊,内容/结构差距(若有)沿 pipeline 自动流转到架构优化分支评估+改造。纯文风轮到"抽象优化与回填"即止,不硬触发架构优化。

1. **用词优化-逆向提取**:读范文,逆向填出中间产物(骨架),剥掉一切用词/句子/腔调。
2. **用词优化-盲重建**:**换一个没看过原文的 agent**,拿骨架走现有正向链盲写这一章。
3. **用词优化-对比差距**:盲重建稿 vs 原文,逐维度只比用词/句子/风格,输出抽象倾向差距清单。
4. **用词优化-抽象优化与回填**:差距过两道闸(防过拟合→定位到层),产出抽象优化建议;**直接三路回填**(①通用层抽象 / ②目标包`01-风格纪律`抽象 / ③目标包`02-范文例库`放例子),执行后回报,并可再跑第2-3步看差距是否收敛(闭环迭代)。

## 中间产物归档（★仿正文的固定文件结构）

本工坊每一轮的中间产物**优先落盘到目标文风包内** `ENGINE/文风库/<目标包>/04-优化留档/<范文标识>-<日期>/`（让成长史跟包走；结构规范见该目录 `_说明.md`）。旧的 `ENGINE/_用词优化留档/<范文标识>-<日期>/` 保留历史数据、不再是新跑档默认落点。两处**槽位编号一致**：

| 编号 | 内容 | 产出步 |
|---|---|---|
| `00-范文原文.md` ★标准 | 标杆范文原文 | 逆向提取（存入）·⚠盲重建步禁止打开 |
| `01-逆向骨架.md` | 剥掉用词的骨架包 | 逆向提取 |
| `02-盲重建稿.md` ★重建 | 拿骨架盲写出的这一章 | 盲重建 |
| `03-对比差距.md` | 抽象倾向差距清单 | 对比差距 |
| `04-优化建议.md` | 对各文风层的抽象建议 | 抽象优化与回填 |

`00`(标准) 与 `02`(重建) 同放一个文件夹，`diff 00 ↔ 02` 即「重建 vs 标准」对比。迭代多轮时 `02/03/04` 加 `-r2 -r3` 后缀，`00/01` 不变。**注意铁律1**：两份放一起只为事后对比，执行盲重建的 agent 仍严禁打开 `00`。

## 使用方式

- 全程带跑:「跑用词优化工坊,范文＝<某章/贴文>」→ 依次跑上面四步。
- 半自动:贴范文一章 + (可选)指定要重点对标的维度(用词/句子/风格)。

## ★ 规模提示

这是**多子agent高消耗**流程(逆向提取1 + 盲重建1~若干 + 对比1 + 优化1,可能迭代多轮)。**每次跑前先报规模、经作者同意再跑。**
