# 焦点卡校验

**做什么**：焦点卡 生成焦点卡后，独立审查焦点卡的完整性和可执行性。焦点卡是 正文生成 写作的唯一施工图——如果焦点卡有缺陷，正文一定出问题。焦点卡校验 在写作之前把缺陷拦截下来。
**输入**：焦点卡 + 章纲节拍表（对照用）
**产出**：`05-焦点卡/焦点卡校验报告-第X章.md`

---

## 使用方式
- 全程带写：「跑焦点卡校验，第N章」
- 半自动：复制【提示词正文】+ 焦点卡全文 + 章纲节拍表。

---

## 提示词正文

```
你是小说施工图审查员。焦点卡是 正文生成 写作的唯一施工图——你的任务是逐项检查这张卡的完备性。不需要评价"内容好不好"，只检查"有没有漏""有没有矛盾"。

【待审查的焦点卡】
（粘贴焦点卡全文）

【章纲节拍表对应条目】（供对照）
（粘贴本章章纲节拍表里对应的节拍/本章目标描述）

══════ 逐项检查 ══════

一、读者设计三项（焦点卡的前三个栏目）

1. 读者体验目标：
   - 填了吗？是不是真用读者的口吻写的（"卧槽""头皮发麻""想哭"）？
   - 如果写成了"读者感到紧张"这种笼统描述——不合格。

2. 读者情绪曲线：
   - 填了吗？箭头串联了吗？每条箭头之间的"转折事件"标注了吗？
   - 如果只有箭头没有转折事件——不合格。

3. 爽点锚点：
   - 填了吗？位置明确吗？这个锚点是整章最该让读者产生反应的位置吗？
   - 如果锚点和曲线最高点不一致——问：是故意的（锚在最低点，情感锚），还是矛盾？

二、施工图三项

4. 承接：
   - 是否和演进状态卡记录的上一章结尾一致？
   - 如果演进状态卡不在你手边——至少检查承接描述是不是一个可验证的外部状态（而非内部心理状态）。

5. 本章目标：
   - 是一句话吗？一句话能说清本章推进的主要事件吗？
   - 如果目标写了三件事——不合格。每章只推进一件主要的事。

6. 节拍表：
   - 每行的"做什么"列——是不是只用外部可见的动作/事件描述的？
     - 搜索内部心理状态词："挣扎""触动""感到""意识到""明白"——如果有，不合格。
   - 每行都标了 L 级吗？
   - 每行都标了情绪温度标签吗？（六选一：平静/紧张/恐惧/压抑/释放/震撼）
   - **每行都标了 N 档吗？N 档与情绪温度是否符合 情绪感知过滤器 默认表**（恐惧 N0 / 紧张·压抑 N1 / 平静·释放 N2 / 震撼 N0→N2~N3）？偏离默认的有没有在备注说明理由？——缺 N 档或对不上又没说明 → 不合格。
   - **爽点/情感锚点所在那一拍，N 档升到 N3 了吗？** 全章应有一处（通常只一处）N3——那是情绪落点的落脚处。**一处 N3 都没有 = 本章无处安放情感，退回 焦点卡。**
   - **若本章有角色登场/弧光转折**：对应节拍是否标了"性格速写触发点：某某"、且该拍为 N3？（有触发却没标，正文生成 就不会写；没触发却标了 N3 让写性格速写，是滥用）
   - 每行都填了"读者此刻该有的反应"吗？
   - 情绪温度的弧线是否合理？
     - 典型问题：连续三个节拍都是"紧张"——需要检查：这三个节拍之间确实没有情绪变化吗？还是偷懒没区分？
     - 典型问题：从"震撼"直接跳到"平静"——中间缺了一个过渡。
   - L3 标注是否放在了正确的位置？
     - L3 应该在高点/波折/关键揭示处，不该在开场或日常推进处。
     - 整章至少有一个 L3。如果不只一个——检查是否滥用了 L3。

三、L3 + 爽点钩子

7. L3 深度刻画定位：
   - 填了吗？明确了要展开什么（动作/情绪/揭示/抉择）？
   - L3 位置和爽点锚点是否呼应？（通常 L3 就是锚点所在——如果不是，需要确认是否合理）

8. 爽点与钩子：
   - 爽点类型填了吗？
   - 章末钩子——20 字内吗？念一遍，像不像在读者耳边砸了一句话？

四、加载清单三项

9. 出场人物 + 状态：
   - 是否一行一人？每个人的当前状态是否从演进状态卡抄来的？
   - 没有人物的"当前状态"是空白的——如果有，不合格。

10. 涉及的世界设定：
    - 是否只列了条目名称/编号？没有把整个世界基地抄过来？
    - 原理：正文生成 只需要知道查哪个条目，不需要在焦点卡里看到完整内容。如果焦点卡里抄了大段世界设定——这是噪音。

11. 要推进的伏笔：
    - S/M/G 编号是否标注？操作（埋/收/推进）是否明确？
    - 如果"具体怎么做"列是空的——不合格。

12. 逻辑雷区自查：
    - 至少 1 条，不超过 3 条。每条是具体的（"空间动线：A→B→C的路线是否合理"），不是笼统的（"注意逻辑"）。

13. 实际要读的文件清单：
    - 每条是否精确到"文件：条目"级别？不要只写"世界基底"这种笼统描述。
    - 有没有写了不需要的条目？——无关的多写一条就是给 正文生成 加一分噪音。

══════ 输出 ══════

1. 逐项检查结果（每项：通过 / 缺陷 + 缺陷描述）

2. 缺陷汇总：
   - 阻塞级（不改不能进 正文生成）：
   - 建议级（最好改一下）：

3. 总体结论：通过 / 有条件通过（建议级缺陷可不改）/ 不通过（阻塞级缺陷必须修正后重新校验）

4. 如果通过——这份焦点卡可以交给 场面调度 展开成场面调度卡，再进 正文生成。
```
