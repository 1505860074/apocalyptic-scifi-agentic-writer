# 人物状态账本 · 模板

> **一人一个文件**，存到 `03-人物/状态账本-XXX.md`（XXX为人名）。只给需要精确追踪状态的人建（主角+核心配角+需要数值校验的人），龙套不建。
> **和人物设定卡（人物卡-核心/人物卡-普通）的分工**：设定卡管"短期不变、重大转折才变"的东西（性格/价值观/说话方式）；这张账本管"随故事弧频繁变"的东西（能力等级/社会地位/金钱/身份/装备等，具体追踪哪些维度看本书的 人物状态维度定义 维度定义表）。
> **追踪哪些维度不是这张卡自己决定的**——照抄 `01-设定/人物状态维度定义.md`（人物状态维度定义）里勾选为"本书追踪"的维度，别自己加维度。

---

## 结构说明（这张账本分两块，各管各的）

- **上半「当前值快照」**：每个维度最新是多少，一眼可查。写下一章前读它就知道这个人现在什么状态。**它是"缓存"，不是历史真相**——每次有变化时，把变的那一个维度的值改掉（只改那一个数字，不重写整张卡）。就算它改错了，靠下半的流水能重算回来。
- **下半「变更流水」**：只往末尾追加，**永远不改旧行**。每次某维度发生变化，在末尾加一行。这是历史真相，是校验的最终依据。

**为什么这么设计**：写入侧几乎纯增量（流水只追加、快照只动一个数字），不用每章重写整张卡——避免大模型改长文档改错改丢；读取侧看快照一眼可查；校验侧 独立正文自查 有明确的"标准答案"可比对。

### 下半 · 变更流水（只追加，不改旧行）

| 第几章 | 维度 | 变化（旧值→新值） | 触发事件（一句话，为什么变） |
|---|---|---|---|
| 初始 | （建卡时的起点值，逐维度列一遍） | — → 初始值 | 建卡 |
| | | | |

> **追加规则**：某章正文里这个人的某维度确实发生了变化，就在这里加一行；同时把上半快照对应维度的"当前值"和"最后更新章"改掉。
> **不变的章不用加行**——大多数章这个人的大多数维度都不变，账本增长很慢，不是每章都膨胀。

## 使用流程

1. **建卡时机**：故事种子与世界基底（新书播种）或角色首次登场时，给需要追踪的人建这张账本，"初始"行逐维度登记起点值。
2. **写作时读**：焦点卡 生成焦点卡时，把出场人物账本的"当前值快照"纳入加载清单 → 正文生成 写正文时照着当前值写，不会把工资写错、把还没升的等级写高。
3. **写作后写**：每章 独立正文自查 校验通过、正文定稿后（跟更新伏笔登记表/演进状态卡同一个收尾动作），检查本章有没有状态变化——有就追加流水行 + 改快照。
4. **校验**：独立正文自查 拿正文里出现的状态值跟账本当前值比对（硬矛盾→必须修），并检查正文里明显变了的状态账本有没有漏登记（漏登记→提醒补）。
