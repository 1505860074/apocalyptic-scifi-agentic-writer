# 归档结构规范（草案 v0.1）

> 本文件定义整条流水线**每一层、每一步的输出如何归档**，使得任何一章读着"奇怪"时，都能顺着档案回溯到**是哪一步把它写歪的**。
> 命名一律用整洁中文步骤名（不用 P/L/V 代号，与立项工坊的命名方向一致；需对照旧代号时在括号里注明）。
> 权威流程仍以 `工作流总览.md` 为准，本文件只补充"产出物怎么落盘"这一层，不改流程本身。

---

## 一、为什么要有这份规范（问题根因）

现在的链条是「一路覆盖」+「报告不落盘」：

- 正文经历 **正文生成（初稿）→ 自查修正（覆盖）→ 润色定稿（覆盖）**，三版压成一版，中间态全丢。
- 焦点卡校验 / 独立正文自查 / 最终交付检查 / 回归校验 这些**校验报告根本没有作为文件留存**（尽管铁律第12条要求"自查报告必须独立存档"）。
- 章纲节拍表也没单独落盘。

结果：一章出问题时，无法回看"是焦点卡就设歪了、是初稿写飞了、是自查修正改坏了、还是润色把味道润没了"。

**本规范的解法**：把「覆盖」改成「每一步留一份不可变快照」，把「没落盘的报告」强制落盘，并给每份档案加一个**溯源信息头**，说明它由哪一步产出、吃了哪些输入、依据哪些规则、上一版是谁。

---

## 二、四条核心原则

1. **不可变快照（immutable）**：每一步的产物一旦生成，**只增不改**。下一步要改，是产出一份**新文件**，不是覆写上一份。
2. **固定语义槽位编号**：每份过程文件用两位数字前缀（`00- 01- 02-`），**编号绑定固定步骤**。某步没触发（如没跑自查修正）就没有那个编号的文件，编号可以跳号，**跳号本身就是"这章没跑那一步"的记录**。跨章看同一个编号=同一步，便于横向对比。
3. **溯源信息头**：每份档案顶部带一段 YAML frontmatter（见第五节），回答"我是谁生的、吃了什么、依据什么、上一版是谁"。
4. **对外入口稳定**：每一章对外的权威正文永远是固定文件名 `正文.md`，不随中间步数增减而变。下游（拼稿、导出、复审修改）只认这个名字，不受过程文件影响。

---

## 三、章节工坊：每章一个"过程文件夹"

每写一章，在 `04-正文/` 下开一个与本章同名的子文件夹，收纳这一章**从正文生成到定稿**的完整生产链：

```
04-正文/
├── 第8章-星海弃兵/
│   ├── 00-焦点卡快照.md          ← 本章正文所依据的焦点卡（从 05-焦点卡 拷入的只读快照）
│   ├── 01-初稿-正文生成.md        ← 正文生成（旧代号 P6）的产物
│   ├── 02-自查报告-独立正文自查.md  ← 独立正文自查（旧 V4）报告【强制落盘，兑现铁律12】
│   ├── 03-修正-自查修正.md        ← 自查修正（旧 P6fix）产物〔仅触发时才有〕
│   ├── 正文.md                   ★ 对外定稿 = 润色定稿（旧 P7）产物，唯一权威入口
│   └── 05-交付报告-最终交付检查.md  ← 最终交付检查（旧 V5）报告〔仅触发时才有〕
├── 第9章-XXXX/
│   └── ...
```

### 说明

- **`正文.md`（无数字前缀）= 当前对外权威定稿**。它同时就是"润色定稿这一步"的产物快照，不再另存一份带序号的定稿，避免冗余。
- **带 `NN-` 数字前缀的文件 = 生产过程留档**，编号即执行顺序。
- **`00-焦点卡快照.md`** 是把 `05-焦点卡/焦点卡-第X章.md` 定稿那一刻拷进来的**只读副本**，作用是钉死"本章正文是基于哪一版焦点卡写的"（焦点卡后续若被改，快照不动，追责时有据）。
- 排查时：一个文件夹从上到下读，就是这一章的完整病历。

> 注：本布局对齐你在选型时确认的 preview，仅把定稿名从 `04-P7终稿.md` 改成固定名 `正文.md`，让对外入口不随步数漂移。

## 四、施工图区（`05-焦点卡/`）：补齐 + 加溯源头

正文生成之前的"施工图"（状态清单 / 节拍表 / 焦点卡 / 焦点卡校验）仍留在 `05-焦点卡/`，但要**补齐目前缺失的落盘**，并统一加溯源头：

```
05-焦点卡/
├── 章节状态清单-第X章.md        （章节状态分配产出，已有）
├── 章纲节拍表-第X章.md          （章纲节拍表产出）【补落盘】
├── 焦点卡-第X章.md              （焦点卡产出，已有）
└── 焦点卡校验报告-第X章.md      （焦点卡校验产出）【补落盘，现在缺失】
```

`00-焦点卡快照.md` 的溯源头里注明"上游施工图见 `05-焦点卡/*-第X章.md`"，两个目录互相指路，全链可串。

## 五、溯源信息头（每份档案顶部）

统一用 YAML frontmatter。字段：

```yaml
---
书: 星海弃兵
章: 第8章
步骤: 润色定稿          # 整洁中文步骤名（旧代号可括注：润色定稿(P7)）
步骤类型: 生成          # 生成 | 校验（生成=P步，校验=V步）
上游:                   # 这一步吃的上一版快照（可多个）
  - 03-修正-自查修正.md
输入:                   # 这一步还加载了哪些文件（设定卡/K规则/焦点卡等）
  - 00-焦点卡快照.md
  - ENGINE/knowledge/去AI味与叙事质感.md
应用规则:               # 用到的知识库规则（整洁名，可括注 K 号）
  - 去AI味与叙事质感
  - 描写与逻辑规范
产出时间: 2026-08-12
执行: Claude Code / opus-4-8
---
```

- **生成步**（正文生成/自查修正/润色定稿）：`上游` 指向它改的那一版，排查时 diff `本文件` ↔ `上游` 就能看出"这一步动了什么"。
- **校验步**（各自查/校验报告）：`步骤类型: 校验`，`上游` 指向它体检的那一版正文。
- 时间由执行该步的 agent 写入（用当天日期）。

## 六、编号槽位总表（章节工坊）

一章从头到尾的完整顺序、每步落到哪、什么时候才有：

| 顺序 | 步骤（整洁名 / 旧代号） | 落点 | 触发条件 |
|---|---|---|---|
| 1 | 章节状态分配 | `05-焦点卡/章节状态清单-第X章.md` | 每章 |
| 2 | 章纲节拍表 | `05-焦点卡/章纲节拍表-第X章.md` | 每章 |
| 3 | 焦点卡 | `05-焦点卡/焦点卡-第X章.md` | 每章 |
| 4 | 焦点卡校验 | `05-焦点卡/焦点卡校验报告-第X章.md` | 每章 |
| — | （焦点卡快照拷入正文文件夹） | `04-正文/第X章-.../00-焦点卡快照.md` | 每章 |
| 5 | 正文生成 (P6) | `.../01-初稿-正文生成.md` | 每章 |
| 6 | 独立正文自查 (V4) | `.../02-自查报告-独立正文自查.md` | 每章（强制） |
| 7 | 自查修正 (P6fix) | `.../03-修正-自查修正.md` | 仅自查判定"必须修"时 |
| 8 | 润色定稿 (P7) | `.../正文.md`（对外定稿） | 每章 |
| 9 | 最终交付检查 (V5) | `.../05-交付报告-最终交付检查.md` | 仅润色有实质改动时 |
| 10 | 章末收尾 | 更新全局活文档（见第七节），不进本章文件夹 | 每章 |

> 章末收尾更新的是伏笔登记表 / 状态账本 / 命名与术语表 / 演进状态卡，这些是**全书共享的活文档**，不是本章私有产物，所以不放进章节文件夹（处理方式见第七节）。

## 七、非章节工坊：成品是"活文档"，报告强制落盘

立项 / 架构 / 世界线 / 故事弧 这些层，它们的成品（世界观卡、人物卡、故事弧大纲、状态预算、伏笔登记表……）是**会随剧情持续增量更新的活文档**，给它们做"逐版快照"会文件爆炸且没意义。所以策略是：

1. **成品保持单文件活文档**（原地更新），位置不变（`00-立项/` `01-设定/` `02-大纲/` `03-人物/`）。
2. **每一道校验门的报告一律强制独立落盘 + 带溯源头**。这是"排查是哪层出问题"的核心证据，现在恰恰大量缺失，必须补：

| 校验门 | 报告落点 | 现状 |
|---|---|---|
| 立项自查 | `00-立项/立项自查报告.md` | 补 |
| 架构一致性校验 | `01-设定/架构校验报告.md` | 补 |
| 焦点卡校验 | `05-焦点卡/焦点卡校验报告-第X章.md` | 补 |
| 独立正文自查 | `04-正文/第X章-.../02-自查报告-独立正文自查.md` | 补（兑现铁律12） |
| 最终交付检查 | `04-正文/第X章-.../05-交付报告-最终交付检查.md` | 补 |
| 回归校验 | `04-正文/第X章-.../06-回归报告-回归校验.md` | 补 |

3. **活文档的历史版本**若确需留痕（如故事弧中途重算了状态预算），把旧版归入 `_过程留档/`（按 层/时间 命名），保持成品目录干净。这条按需，不强制。

## 八、怎么用这套档排查"哪层写奇怪"

标准动作（从成品往回倒查）：

1. 读 `正文.md`，圈出读着别扭的段落。
2. diff `正文.md` ↔ `03-修正-自查修正.md`：润色这一步动了这里吗？→ 是，问题在**润色定稿**。
3. diff `03-修正...` ↔ `01-初稿...`：自查修正动的？→ 是，问题在**自查修正**（对照 `02-自查报告` 看它当时判了什么）。
4. 若初稿 `01-...` 里就已经歪了 → 问题在**正文生成**，再看 `00-焦点卡快照.md`：是焦点卡本身就把这一拍设错了吗？→ 是，问题在**焦点卡 / 焦点卡校验**这一层。
5. 每份档案的溯源头 `应用规则` 字段，直接告诉你"这一步是依据哪条 K 规则做的"，可顺藤查是不是那条规则本身有问题。

一句话：**从 `正文.md` 一路往编号小的方向 diff，第一处出现"奇怪"的快照，就是引入问题的那一层。**

## 九、待你拍板的几个点

以下是写规范时替你做的默认决定，**请重点确认或推翻**：

- **A. 定稿固定名用 `正文.md`**（比 preview 的 `04-P7终稿.md` 更稳，对外入口不漂移）。认可否？
- **B. 施工图（节拍表/焦点卡/焦点卡校验报告/状态清单）留在 `05-焦点卡/`**、只补齐落盘，不并进每章文件夹。若你想"一个文件夹装下从状态清单到定稿的一整章"，我可以改成全链收纳。选哪个？
- **C. 已写的 8 章**：保持原样、新结构从**第 9 章**起启用（推荐，最省事）；还是把已写 8 章的正文也**归位**进新文件夹结构（只迁定稿正文到 `第X章/正文.md`，中间态确实已丢、不伪造）？
- **D. 非章节工坊策略**（第七节）：成品保持活文档、只强制补校验报告落盘，**不给设定卡做逐版快照**。认可否？
